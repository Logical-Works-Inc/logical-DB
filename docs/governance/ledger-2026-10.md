### 2026-11-03 — Public repository, Apache-2.0, GitHub-hosted CI

Director ruling, 2026-11-03: the repository becomes public under Apache-2.0,
CI moves to GitHub-hosted runners (free for public repositories), and external
contributions are not accepted at this stage. This supersedes the 2026-09-14
ruling that Actions was billing-blocked and the FDB lane self-hosted.

- `LICENSE` is the verbatim Apache License 2.0 text from apache.org, pinned in
  `clean_room_evidence.rs` by its git blob id; it is the only uncited file.
- Every job runs on a pinned hosted image (`ubuntu-24.04`, `macos-15`,
  `windows-2025`). The repository-level self-hosted runner is deregistered and
  both organization runner groups refuse public repositories.
  `crates/logical-db-e2e/tests/ci_routing.rs` refuses self-hosted, moving, and
  unresolved labels.
- The Python verifiers `verify-rewrite.py` and `verify-ci.py`, `ci-local.sh`,
  `ci-fdb-linux.sh`, and the Wine/Docker/VM emulation lanes are retired (moved to
  Trash). Their gates are Rust: the `clean_room_evidence` and `ci_routing` tests
  and the `ci_local` binary. The FDB lane is one composite action,
  `.github/actions/fdb-lane/action.yml`. Windows is now native MSVC.
- Language law, Director 2026-11-03: product code is Rust, C++, or C (the
  languages FoundationDB itself uses). The three remaining domain and access
  graph scripts run unchanged until their Rust port.
- Estate edges move to the newest releases: `lgwks_bot` 6.1.0, `lgwks_std`
  3.2.2, `lgwks_deps` 5.1.2, with a full `cargo update` (`cargo audit`: zero
  vulnerabilities). The 2026-10-05 license exception is closed:
  `contract/APPROVED.toml` declares `accepted_licenses` including `MPL-2.0`,
  and `deny.toml` admits `MPL-2.0` for `lgwks_bot` only.
- `CONTRIBUTING.md` states the no-external-contribution rule. Interactions
  are limited to collaborators (GitHub interaction limits), every fork pull
  request run needs approval, private vulnerability reporting is on, and the
  wiki is off. GitHub does not allow disabling forks of a public repository.
- `README.md`, `WORKFLOW.md`, and this file are split under the 120-line
  document law into `docs/EMBEDDING.md`, `docs/workflow/`, and
  `docs/governance/`, moved verbatim.

**Does not claim:** production completion; issue #28 closure; any nine-axis
green; any hosted lane result beyond the run recorded on the pull request.

### 2026-10-05 — Estate 1.0.0 upgrade merged under a bounded license exception (PR #109)

The lgwks 1.0.0 estate upgrade on `chore/estate-1-0-0` (PR #109)
merges with a bounded exception the Director authorized on
2026-10-05. The exception covers exactly the three license
refusals the stricter estate gate reports, all unfixable from this
repository:

- `lgwks_bot` 1.0.0 declares `MPL-2.0`; `lgwks_deps` 1.0.0
  hardcodes its accepted-licenses set and refuses `MPL-2.0` as an
  inbound dependency license, and the `cargo deny` licenses lane
  rejects the same identifier.
- `foundationdb` and `foundationdb-tuple` 0.11.0 declare the
  legacy slash form `MIT/Apache-2.0`; the estate gate compares the
  declared expression against the register entry with exact
  equality (`license_refusals` in `lgwks_deps`), and no valid SPDX
  expression the register parser accepts can equal that declared
  string.

Replacement evidence: `evidence/ci-local-862cf43.md` — 13 of 15
lanes pass; the tests lane fails only the two dependency-contract
assertions that demand zero refusals, and the deny lane fails only
`lgwks_bot`'s license. The register drift the 1.0.0 gate exposed
otherwise is fixed in 862cf43 (`logical-db-cloud-contract` added
to the `thiserror` and `uuid` consumer lists).

Follow-up on the estate side (logicalworks-crates), as the Director
stated: admit `MPL-2.0` inbound in the accepted set (a Director
decision per `lgwks_deps`' own documentation) and normalize the
declared slash form to its SPDX `OR` equivalent; then add `MPL-2.0`
to `deny.toml`'s allow list here and close this exception. This
entry claims neither hosted nor self-hosted CI execution nor a
ratified license policy.
